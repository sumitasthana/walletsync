Project Overview

WalletSync

A pipeline that turns Chase credit card web pages and rewards PDFs into clean, validated, machine-readable JSON. It pulls pricing terms (APRs, fees, intro offers) and rewards program details (earning rates, redemption options, transfer partners) for 41 cards, then merges them into one dataset you can query, compare, and build on.

What we are doing here

Credit card terms are scattered across HTML pricing pages (the legally required Schumer Box) and multi-page rewards agreement PDFs. The format is meant for humans, not software. WalletSync reads those sources, extracts the important fields, and writes them into a typed schema (Pydantic models) so downstream code can trust the structure.

The project takes a two-track approach, because the two source types are very different:

Pricing: deterministic parsing

Path B

Pricing pages are already HTML tables, so we parse them with BeautifulSoup and extract values with regex. This is fast, free, and cannot invent values that are not in the source. Result: 100% of 41 cards, $0 cost, under one second.

Rewards: LLM extraction

AWS Bedrock, Claude 3 Haiku

Rewards agreements are unstructured PDF text, so an LLM reads them and fills the schema. A fallback path extracts earning rates from the product page HTML when no PDF exists. Each record is tagged with a data quality tier so consumers know how much to trust it.

The pipeline

STAGE 1
Raw dumps
Scrape pricing HTML to JSON; download rewards PDFs to text.
→
STAGE 2
Structured extraction
Deterministic parser for pricing; LLM for rewards. Validated against Pydantic schemas.
→
STAGE 3
Merge and save
Combine pricing, rewards, and base card info into one JSON per card.

The CLI (extract_card_data.py) ties the stages together with a resume feature: it skips cards already processed, so a crash or a daily refresh only pays for new work.

Use cases

Card comparison tools

Compare APRs, fees, and earn rates side by side across all 41 cards. The flat schema makes sorting and filtering trivial: "no-annual-fee cards with 3x dining" is a one-line query.

Rewards optimization

For Tier 1 cards, compute the best redemption per point and the best transfer partner ratio. Build a "which card for this spend" recommender from the earning categories.

Signup bonus tracking

The schema captures bonus value, spend requirement, and the months to hit it. A dashboard can surface time-limited offers and flag cards whose bonus disqualifying products apply.

Cost-of-carry modeling

Feed pricing fields (APR ranges, balance transfer fees, intro windows) into a calculator that models interest over time, or compares a balance transfer vs. carrying a balance.

Change monitoring

Re-run the pipeline on a schedule and diff the JSON. Because pricing is deterministic, any change in an APR or fee is a real issuer change, not parser noise. Alert on it.

Training data and RAG

The clean records are a ready dataset for a card-recommendation assistant. Pair the JSON with a vector store and an agent can answer "best Chase card for international travel" from grounded, validated data instead of guessing.

Potential benefits

  • Trustworthy financial data. Pricing comes from deterministic parsing, so a number in the dataset always traces back to a specific HTML table row. No black box.
  • Low, predictable cost. A full 41-card run costs about $0.14. The pricing half is free; only the unstructured rewards PDFs call the LLM.
  • Resumable and cheap to refresh. Skip logic means a daily re-run only pays for cards that changed or were not yet processed.
  • Typed contracts for consumers. Pydantic models and the data_quality_tier field let downstream code branch on confidence instead of guessing whether a field exists.
  • Reproducible. Same input, same output. Deterministic parsing makes bugs debuggable and unit-testable, which is hard with LLM extraction.
  • A foundation, not a one-off. The parser-first lesson (use structured parsing for structured sources, LLM only for unstructured ones) generalizes to other banks and other regulated disclosure formats.

Next steps

1. Close the rewards gap

Fix the 14 LLM category-validation failures by adding explicit category mappings to the prompt and expanding ALLOWED_CATEGORIES where a co-branded category is genuinely needed. Expected gain: roughly 10 to 12 cards move up to Tier 1, at about $0.04.

2. Backfill flagship transfer partners

Sapphire Reserve and Sapphire Preferred are Tier 2 today, so they are missing transfer partner and redemption multiplier data that matters most for premium cards. Either enhance the scraper to visit product detail pages or add a manual override file for these few cards.

3. Add scheduled change detection

Wire the pipeline to run on a schedule, diff the new JSON against the last run, and alert on changed pricing fields. Deterministic output makes this reliable.

4. Implement URL-based extraction

The --url flag is stubbed out. Finishing it lets the pipeline accept any Chase card page on demand, not just the 41 in the cleaned dataset.

5. Build a downstream app

Use the merged dataset as the backend for a comparison site, a card-recommendation assistant, or a personal wallet tracker. The schema is already the contract.

6. Generalize beyond Chase

The deterministic-first approach should transfer to other issuers whose pricing pages use HTML tables. Abstract the parser per issuer and keep one shared output schema.
